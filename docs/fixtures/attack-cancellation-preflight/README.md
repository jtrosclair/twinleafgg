# Attack cancellation preflight research — not for integration

The existing `round28-nontarget-cancellation.red.spec.fixture.ts` demonstrates that Clefable JU Metronome copying Scratch can deal damage even after Sandshrew BS's Sand Attack flips tails. Some direct attacks also perform side effects before the asynchronous flip finishes. This directory preserves an isolated prototype and the evidence that it is **not safe to ship**.

`candidate.patch` applies to the working-tree source identified by `candidate-manifest.tsv`; it adds an attack-start cancellation event, opts Sandshrew BS, Sandile BLW, Flareon DEX and Hippopotas PRC into it, forwards checked ownership through copied attacks, and preserves after-attack event dispatch. It also moves the existing Clear Vision and copied opponent attack checks ahead of the coin. The two unannotated copied-handler ownership acceptance tests are unchanged. Other cancellation blockers, including Weezing DX and Seadra DF, are not migrated.

`metronome-orchestration.spec.fixture.ts` covers direct and copied attacks, cancellation before side effects, nested copy chains, both coin outcomes, simultaneous blockers, direct raw `AttackEffect` calls, copied restrictions, serialized and restored markers, store isolation, error cleanup, Clear Vision, copied Iron Rule and native Iron Rule. The last test is intentionally **red** under the candidate. `sirfetchd-legality.spec.fixture.ts` is an independent reproduction with an attack-specific Meteor Assault reuse lock; both coin outcomes are red under the candidate and pass with the baseline generator restored. `metronome-cleanup.red.spec.fixture.ts` uses a synthetic pre-existing engine rearm flag to confirm that the regular `AfterAttackEffect` and its cleanup are preserved. The original red fixture remains in its existing location.

The candidate incorrectly handles native Cobalion-GX Iron Rule together with Sandshrew's marker: on tails, it flips and consumes the attack instead of rejecting the illegal attack first. Galarian Sirfetch'd RCL Meteor Assault likewise bypasses its reuse restriction on tails and flips before rejecting on heads. With just the baseline attack generator restored in the otherwise identical scratch workspace, the native Iron Rule test passes; the prototype fails both the expected exception and the no-flip assertion. This is a behavioral regression, not merely a missing card feature. `native-attack-throw-inventory.txt` lists 92 AST-selected `if` branches whose condition mentions `instanceof AttackEffect` and whose body contains `throw new GameError`; these are **audit candidates, not 92 verified legality checks**. Some refer to attack-specific requirements, not opposing restrictions. Other syntactic shapes and helper calls are outside this scan.

The previously tested selective prototype, before adding the native-Iron-Rule red assertion, passed 511 tests across 23 isolated spec files; the two pre-existing unannotated ownership acceptance assertions failed. The focused cancellation suite had 38 passing assertions. A separate direct native Iron Rule test failed as described above. The saved-puzzle comparison found 534/534 comparable states valid with identical serialized and deserialized outputs, and 3,487/3,487 first-action outcomes matched (1,878 Trainer, 688 attack and 921 Ability actions). These samples do not cover the native-Iron-Rule/Sand-Attack combination and therefore do not establish safety. Both API bundles used the same esbuild and TypeScript configuration. In-flight prompt callbacks are not restored by `Store.restoreState`; the restored-marker tests begin from a stable saved state.

To reproduce, use an isolated copy of the shared working tree matching the manifest. From its root, verify and apply the patch, then install the fixtures as test files:

```sh
git apply --check docs/fixtures/attack-cancellation-preflight/candidate.patch
git apply docs/fixtures/attack-cancellation-preflight/candidate.patch
cp docs/fixtures/attack-cancellation-preflight/metronome-orchestration.spec.fixture.ts ptcg-server/src/sets/tests/metronome-orchestration.spec.ts
cp docs/fixtures/attack-cancellation-preflight/metronome-cleanup.red.spec.fixture.ts ptcg-server/src/sets/tests/metronome-cleanup.spec.ts
cp docs/fixtures/attack-cancellation-preflight/sirfetchd-legality.spec.fixture.ts ptcg-server/src/sets/tests/metronome-sirfetchd.spec.ts
cp docs/fixtures/round28-nontarget-cancellation.red.spec.fixture.ts ptcg-server/src/sets/tests/metronome-cancellation.spec.ts
cd ptcg-server
node scripts/test-card-regressions.cjs '--filter=metronome|copied|upstream-round31|latios-clear-vision' --keep-workspace
```

The native-Iron-Rule test should fail on the prototype. Verify the test's baseline control in a separate isolated copy without the patch: use only that test, since the rest of the orchestration fixture expects the prototype's new interfaces and behavior. The saved-puzzle tools are `tools/compare-puzzle-corpus.cjs` and `tools/compare-puzzle-actions.cjs`; both use read-only database access.

A safe next step is to classify the 92 candidates and additional helper-mediated restrictions, and give pure legality checks an explicit ownership contract covering both native and copied sources. Legality must run before cancellation flips and attack-owned side effects, exactly once per actual attack; copied and direct attacks need identical enforcement. Then migrate the remaining cancellation sources, covering simultaneous blockers, nested copies, source removal, both coin outcomes, state restoration and error/async cleanup. Preserve the generic `AfterAttackEffect` lifecycle, while attack-owned after-attack branches must distinguish cancellation. Re-run the red tests, existing compatibility suite and saved-puzzle/action comparisons before integration; card reducers must not be speculatively executed against live state to infer legality.
